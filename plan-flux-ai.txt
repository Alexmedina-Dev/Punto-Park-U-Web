╔══════════════════════════════════════════════════════════════╗
║  2. MÓDULO 1: VISIÓN COMPUTACIONAL (Python + OpenCV)       ║
╚══════════════════════════════════════════════════════════════╝

  📸  ¿Qué hace?
      Reconocimiento de matrículas, marca, modelo y color
      de vehículos usando una cámara en la entrada.

  🛠️  Stack técnico (100% gratuito):
      - Python 3.11+ (gratis)
      - OpenCV (gratis, open source)
      - EasyOCR (gratis, open source)
      - YOLOv8 de Ultralytics (gratis para uso no comercial)
      - FastAPI (gratis, open source)

  📦  Dataset:
      - Matrículas colombianas: formato ABC-123 / ABC-12D
      - Matrículas amarillas (público), blancas (particular)
      - Recolección: fotos propias + Google Images con permiso
      - Etiquetado: LabelImg (gratis) o Roboflow free tier

  🧠  Entrenamiento:
      - Modelo base: YOLOv8n (nano — más liviano, funciona en CPU)
      - Entrenamiento: Google Colab FREE (GPU T4, 12h gratis/día)
      - Exportar a formato ONNX (compatible con CPU, sin GPU)
      - Alternativa sin entrenamiento: EasyOCR directo funciona
        bien para matrículas colombianas sin fine-tuning

  ⚡  Inferencia:
      - Tiempo objetivo: < 1 segundo por vehículo (CPU)
      - Se ejecuta como microservicio FastAPI independiente
      - Backend Node.js se comunica vía HTTP/REST

  🎯  Para el MVP educativo:
      - Comenzar con EasyOCR puro (sin YOLOv8)
      - Probar con fotos estáticas antes de cámara en vivo
      - Agregar YOLOv8 en iteración posterior


╔══════════════════════════════════════════════════════════════╗
║  3. MÓDULO 2: ASIGNACIÓN INTELIGENTE (Node.js + Algoritmo) ║
╚══════════════════════════════════════════════════════════════╝

  🅿️  ¿Qué hace?
      Asigna el espacio óptimo a cada vehículo basado en
      múltiples variables en tiempo real.

  🛠️  Stack técnico:
      - Node.js + Express (gratis)
      - Algoritmo propio de puntuación (sin ML, solo lógica)
      - socket.io para actualización en tiempo real (gratis)

  📊  Variables de entrada:
      - Tipo de vehículo (auto, moto, bici)
      - Ocupación actual de cada espacio
      - Tiempo estimado de estadía
      - Preferencias del usuario

  🧠  Lógica del algoritmo:
      1. Filtrar espacios disponibles por tipo de vehículo
      2. Puntuar cada espacio:
         - Cercanía a la salida (+10 pts)
         - Tamaño adecuado (+15 pts si justo)
         - Cubierto / con sombra (+5 pts)
      3. Seleccionar espacio con mayor puntuación
      4. Emitir por WebSocket al dashboard en tiempo real

  ⚡  Performance:
      - Ejecución en < 100ms (Node.js puro, sin Python)
      - 100% gratuito, corre en Railway / Render free tier


╔══════════════════════════════════════════════════════════════╗
║  4. MÓDULO 3: ANALÍTICA PREDICTIVA (Python + ML)           ║
╚══════════════════════════════════════════════════════════════╝

  📈  ¿Qué hace?
      Predice horas pico y detecta anomalías en el parqueadero.

  🛠️  Stack técnico (100% gratuito):
      - Python 3.11+ (gratis)
      - Scikit-learn (gratis, open source)
      - Prophet de Meta (gratis, open source)
      - Joblib para serializar modelos (gratis)
      - FastAPI para servir predicciones (gratis)

  🧠  Modelo de Predicción de Ocupación:
      - Input: hora, día de semana, mes
      - Output: % de ocupación esperada
      - Entrenamiento: datos históricos del parqueadero
      - Primera versión: reglas heurísticas simples
        (lunes-viernes 8am-10am = hora pico)
      - Segunda versión: Prophet con datos reales acumulados

  🧠  Detección de Anomalías:
      - Detecta vehículos que exceden tiempo permitido
      - Alerta visible en el panel de administración

  ⚡  Entrenamiento:
      - Google Colab FREE (suficiente para estos modelos)
      - No requiere GPU — CPU es suficiente para Scikit-learn

║  8. RIESGOS Y MITIGACIONES                                 ║
╚══════════════════════════════════════════════════════════════╝

  ⚠️  Riesgo: Precisión del OCR en matrículas colombianas
     ✅ Mitigación: EasyOCR funciona bien sin fine-tuning.
        Si no es suficiente, agregar YOLOv8 nano en Colab.

  ⚠️  Riesgo: Servicios free tier se duermen
     ✅ Mitigación: Usar UptimeRobot (gratis) para hacer
        ping cada 14 minutos y mantener los servicios activos.

  ⚠️  Riesgo: Datos insuficientes para modelo predictivo
     ✅ Mitigación: Empezar con reglas heurísticas simples.
        Migrar a Prophet solo cuando haya datos reales.

  ⚠️  Riesgo: MongoDB Atlas 512MB insuficiente
     ✅ Mitigación: Para un parqueadero educativo es más que
        suficiente. Monitorear con Atlas Dashboard gratuito.

  ⚠️  Riesgo: Google Colab desconecta en entrenamiento largo
     ✅ Mitigación: Guardar checkpoints cada epoch en
        Google Drive. Retomar desde el último checkpoint.
