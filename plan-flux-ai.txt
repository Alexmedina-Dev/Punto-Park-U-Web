╔══════════════════════════════════════════════════════════════╗
║  2. MÓDULO 1: VISIÓN COMPUTACIONAL (Python + OpenCV)      ║
╚══════════════════════════════════════════════════════════════╝

  📸  ¿Qué hace?
      Reconocimiento de matrículas, marca, modelo y color
      de vehículos usando una cámara IP en la entrada.

  🛠️  Stack técnico:
      - Python 3.11+
      - OpenCV (captura y procesamiento de frames)
      - EasyOCR / PaddleOCR (reconocimiento de texto en matrículas)
      - YOLOv8 (detección y clasificación de vehículos)
      - Modelo propio fine-tuned con dataset colombiano

  📦  Dataset:
      - 50,000+ imágenes de vehículos colombianos
      - Matrículas amarillas (público) y azules (diplomático/oficial)
      - Formatos: ABC-123, ABC-12D, etc.
      - Fuentes: scraping permitido + fotos propias del parqueadero

  🧠  Entrenamiento:
      - Modelo base: YOLOv8 pre-entrenado
      - Fine-tuning con dataset colombiano (transfer learning)
      - Entrenar en Google Colab o servidor con GPU
      - Exportar a formato TensorRT para inferencia rápida

  ⚡  Inferencia:
      - Tiempo objetivo: < 0.5 segundos por vehículo
      - Se ejecuta como microservicio Python independiente
      - Backend Node.js se comunica vía HTTP/REST con el
        servicio de visión


╔══════════════════════════════════════════════════════════════╗
║  3. MÓDULO 2: ASIGNACIÓN INTELIGENTE (Node.js + Algoritmo) ║
╚══════════════════════════════════════════════════════════════╝

  🅿️  ¿Qué hace?
      Asigna el espacio óptimo a cada vehículo basado en
      múltiples variables en tiempo real.

  🛠️  Stack técnico:
      - Node.js (integración directa con el backend React)
      - Algoritmo propio de optimización (no requiere ML)

  📊  Variables de entrada:
      - Tipo de vehículo (auto, moto, camioneta, bici)
      - Dimensiones del vehículo (detectadas por Módulo 1)
      - Ocupación actual de cada espacio
      - Tiempo estimado de estadía
      - Preferencias del usuario (cerca de salida, sombra, etc.)

  🧠  Lógica del algoritmo:
      1. Filtrar espacios disponibles por tipo de vehículo
      2. Puntuar cada espacio según:
         - Cercanía a la salida (+10 pts)
         - Cobertura de cámara (+8 pts)
         - Tamaño adecuado (+15 pts si justo, -5 si sobra)
         - Sombra / cubierto (+5 pts)
      3. Seleccionar el espacio con mayor puntuación
      4. Si el usuario es frecuente, priorizar su zona preferida

  ⚡  Performance:
      - Ejecución en < 100ms (Node.js puro, sin Python)
      - Responde vía WebSocket para actualización en tiempo real


╔══════════════════════════════════════════════════════════════╗
║  4. MÓDULO 3: ANALÍTICA PREDICTIVA (Python + ML)          ║
╚══════════════════════════════════════════════════════════════╝

  📈  ¿Qué hace?
      Predice horas pico, detecta anomalías y optimiza
      la operación del parqueadero automáticamente.

  🛠️  Stack técnico:
      - Python 3.11+
      - Scikit-learn (modelos clásicos: Random Forest, XGBoost)
      - Prophet (predicción de series temporales)
      - Joblib (serialización de modelos entrenados)

  🧠  Modelo de Predicción de Ocupación:
      - Inputs: hora del día, día de la semana, mes,
                clima actual, eventos cercanos
      - Output: % de ocupación esperada por hora
      - Entrenamiento: con datos históricos del parqueadero
      - Re-entrenamiento: semanal automático

  🧠  Modelo de Detección de Anomalías:
      - Inputs: flujo de entrada/salida, duración de estadía
      - Detecta: vehículos que exceden tiempo, accesos
        sospechosos, patrones de uso inusuales
      - Alerta: notificación en el panel de administración

  ⚡  Performance:
      - Predicciones en < 50ms
      - Se ejecuta como job programado (cron) cada hora
      - API REST para consultar predicciones desde React

║  8. RIESGOS Y MITIGACIONES                                 ║
╚══════════════════════════════════════════════════════════════╝

  ⚠️  Riesgo: Precisión del OCR en matrículas colombianas
     ✅ Mitigación: Fine-tuning con dataset local, aumentar
        variedad de condiciones de luz y ángulo

  ⚠️  Riesgo: Latencia alta en visión computacional
     ✅ Mitigación: Usar TensorRT para optimizar inferencia,
        ejecutar en GPU dedicada si es necesario

  ⚠️  Riesgo: Datos insuficientes para modelo predictivo
     ✅ Mitigación: Empezar con reglas heurísticas mientras
        se recolectan datos, luego migrar a ML

  ⚠️  Riesgo: Costo de infraestructura
     ✅ Mitigación: Empezar con servicios free tier,
        escalar solo cuando sea necesario
