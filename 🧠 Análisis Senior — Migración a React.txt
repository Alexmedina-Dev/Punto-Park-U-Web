 1. DIAGNÓSTICO DEL PROYECTO ACTUAL
════════════════════════════════════════════════════════

   Archivos totales: 27 (excluyendo .git)
   Líneas de JS totales: ~2,570
   Líneas de CSS totales: ~8,200
   Páginas: 7 (index, login, registro, user-panel, admin-panel,
             registro-exitoso, pantalla-error)
   Tipo: 100% Vanilla HTML/CSS/JS
   Base de datos: FICTICIA (localStorage/sessionStorage)
                  → Proyecto educativo. Backend real en Fase 5.

   ── Los 6 puntos críticos que van a morder si no se planean ──

   🔴 1. Estado global disperso en localStorage/sessionStorage

      El proyecto tiene estado esparcido en mínimo 6 claves
      distintas sin gestión centralizada:

         localStorage: parkingPrices
         localStorage: parkingSchedule
         localStorage: registeredUsers
         localStorage: notificationSettings
         localStorage: puntoParkUser     ← sesión de usuario
         sessionStorage: adminAuth        ← sesión de admin

      En React → una sola fuente de verdad con Zustand + persist
      middleware (zustand/middleware). Context API sin cuidado
      causa re-renders en cascada.

   🔴 2. Chart.js con instancias globales (window._chart)

      En panel.js:
         window._chartIngresos = new Chart(...)
         window._chartOcupacion = new Chart(...)

      En React esto explota porque el DOM se desmonta y remonta.
      El canvas queda "en uso" y lanza error:

         "Canvas is already in use"

      Solución: useRef para el canvas + useEffect con cleanup
      obligatorio. El hook useDestroyChart debe llamar chart.destroy()
      en la función de retorno del useEffect.

   🔴 3. 40+ inline event handlers mezclados con HTML

      Patrón actual:
         onclick="navigate('dashboard')"
         onsubmit="handleLogin(event)"
         oninput="updatePricePreview()"

      En React → props de evento + useCallback. Si no se
      memoizan, cada render recrea las funciones y causa
      re-renders innecesarios en componentes hijos.

   🔴 4. Guard de auth en top-level del módulo

      En panel.js líneas 3-6:
         if (!isDev && sessionStorage.getItem('adminAuth') !== 'true') {
             window.location.href = '../Admi.html';
         }

      Esto NO funciona en React porque:
      - Corre antes de que el árbol de componentes exista
      - No puede usar React Router (useNavigate)
      - Da falsos positivos si el contexto de auth no está listo

      Solución: authStore (Zustand) + ProtectedRoute component con
      useNavigate(), no con window.location.

   🔴 5. Chart.js destroy/reinit pattern frágil

      Patrón actual:
         function _destroyChart(id) {
             const chart = Chart.getChart(id);
             if (chart) chart.destroy();
         }

      Llamado en múltiples lugares sin garantía de orden.
      En React el patrón correcto es:
         useEffect(() => {
             const chart = new Chart(ctx, config);
             return () => chart.destroy();
         }, [dependencies]);

   🔴 6. jsPDF + xlsx cargados por CDN

      En el HTML actual:
         <script src="...jspdf.umd.min.js"></script>

      Y en panel.js:
         if (typeof window.jspdf === 'undefined') { ... }

      En Vite esto NO funciona porque:
      - No hay window.jspdf en un bundle empaquetado
      - jsPDF y xlsx deben instalarse como npm packages
      - Hay que importarlos como módulos ES

   ── Problemas adicionales ──

   🟡 CSS global sin aislamiento
      Styles.css (1,738) + panel.css (3,068) + pantalla-usuario.css
      (1,796) = ~6,600 líneas de CSS global. Sin encapsulación.
      → Solución: Tailwind CSS (ver Sección 3 — decisión CSS)

   🟡 Rutas relativas frágiles con espacios
      Ej: '../Login/Pantalla%20Usuario/PantallaUsuario.html'
      Dan 404 en producción. React Router usa /dashboard, /admin.

   🟡 Sin TypeScript
      Errores solo en runtime. TypeScript los detecta al compilar.

   ── Decisión CSS: ¿Por qué Tailwind y no CSS Modules? ──

   CSS Modules: CSS normal con scope automático. Cero nueva sintaxis.
   Tailwind: clases utilitarias. Primera hora cuesta, después es más
   rápido que cualquier alternativa.

   ✅ Decisión: Tailwind CSS v3.4
   Razones:
   - Estándar de la industria en proyectos React 2026
   - Los tokens de color del proyecto ya están definidos
     (#10131a, #a7c8ff, etc.) → van directo al tailwind.config.ts
   - Con OpenCode/Copilot la curva de aprendizaje se reduce a la mitad
   - CSS Modules hay que aprenderlo igual eventualmente
   ⚠️ NO Tailwind v4: breaking changes activos, documentación incompleta.

 8. PATRONES CRÍTICOS PARA CHART.JS EN REACT
════════════════════════════════════════════════════════

   ── MAL (patrón actual en panel.js) ──

   window._chartIngresos = new Chart(...)
   // sin cleanup, sin useRef, scope global → memory leak


   ── BIEN (patrón React con useRef) ──

   const chartRef = useRef<HTMLCanvasElement>(null)
   const chartInstance = useRef<Chart | null>(null)

   useEffect(() => {
       const ctx = chartRef.current?.getContext('2d')
       if (!ctx) return
       chartInstance.current = new Chart(ctx, { ... })
       return () => {
           chartInstance.current?.destroy()
           chartInstance.current = null
       }
   }, [data])

   return <canvas ref={chartRef} />


   ── MEJOR (con react-chartjs-2) ──

   import { Doughnut } from 'react-chartjs-2'
   import { Chart, ArcElement, Tooltip, Legend } from 'chart.js'
   Chart.register(ArcElement, Tooltip, Legend)

   // react-chartjs-2 maneja el lifecycle automáticamente

       return <Doughnut data={data} options={options} />

 9. RED FLAGS — ERRORES A EVITAR
════════════════════════════════════════════════════════

   🚩 NO migrar todo de golpe
      Página por página. La app vanilla sigue funcionando.

   🚩 NO mantener ambos paneles en el mismo bundle
      Usar React.lazy() + Suspense para admin y usuario.

   🚩 NO usar Redux
      Zustand es suficiente y más simple para este proyecto.

   🚩 NO mezclar CSS vanilla con Tailwind
      Cuando migres una página, migra TAMBIÉN su CSS.

   🚩 NO escribir componentes sin TypeScript primero
      Las interfaces van ANTES de cualquier componente.

   🚩 NO mantener auth fragmentado
      Unificar en authStore (Zustand) desde el día 1.

   🚩 NO usar Tailwind v4
      V4 tiene breaking changes activos. Usar v3.4.

   🚩 NO dejar jsPDF + xlsx en CDN
      window.jspdf NO existe en Vite. Instalar como npm.
